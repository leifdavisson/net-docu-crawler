### Proposed Canonical Non-Breaking `credentials.json` Schema (for `CD-02` / `CD-04`)
- **Top-level**: JSON array of non-empty profile objects (`list[dict]`).
- **Fields**:
  - `username` (`str`, **required**, trimmed, non-empty).
  - `password` (`str`, optional, default `""`; reject non-string e.g. `null`/int).
  - `secret` (`str`, optional, canonical enable secret, default `""`).
  - `enable_secret` (`str`, optional **deprecated backwards-compatible alias** mapped into `secret` with a clear deprecation warning; reject non-string; error if both `secret` and `enable_secret` are non-empty and disagree).
  - `vendor` (`str`, optional, default `""`; validated against `VENDOR_DRIVER_MAP` and **canonicalized** via `DRIVER_VENDOR_MAP[VENDOR_DRIVER_MAP[v]]` so aliases like `"frr"` -> `"frrouting"` and `"hp"` -> `"hpprocurve"` match `detector.py` scoping; unknown tag emits warning listing valid canonical tags).
  - `name` (`str`, optional, default `<source>[<idx>]`).
- **Unknown keys**: emit clear warning naming only the unexpected key names (never secret values) so typos like `"passowrd"` fail-loudly under `--validate-credentials`.
- **Error reporting**: structured errors for missing file, invalid JSON (line/col), non-list root, non-object item, empty list, missing/empty `username`, wrong field types. Route legacy `load_credentials()` or deprecate it in favor of `load_and_validate_credentials()`.
